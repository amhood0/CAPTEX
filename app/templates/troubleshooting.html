Troubleshooting

Back to Admin

Normal automated runs start the managed VM when needed, prepare the guest, execute tests, and collect results. Use the Admin tools when setup or execution needs attention. Manual testing works without the virtualization prerequisites.

Environments

Environment records describe where a test ran: operating system, version, architecture, and infrastructure mapping. Creating a record does not create or start a virtual machine.

Automated execution currently supports the managed Ubuntu VMware environment. Other records can describe environments used for manual testing. If the managed record is missing, register it from Virtualization.

Virtualization

Checks the host prerequisites and controls the managed Ubuntu VM through Vagrant and VMware Workstation.

  • Check prerequisites: identifies missing VMware, Vagrant, provider plugin, utility, or base-box requirements and shows the next action.
  • Refresh VM status: checks the VM's current state, especially after a timeout or interrupted operation.
  • Start VM / Stop VM: changes the VM's power state. Starting it here does not execute a capability test.

Ansible diagnostics

Ansible runs inside the Ubuntu guest to prepare files and execute automation. Start the VM before using these diagnostic controls.

  • Check connectivity: verifies that CAPTEX can execute a basic command in the guest over SSH.
  • Prepare Ansible and transfer files: installs Ansible if needed and copies the diagnostic assets into the guest. Initial preparation needs internet access.
  • Run validation playbook: prepares the guest and runs a diagnostic playbook, checking for its success marker.

A successful diagnostic confirms the automation path works. It does not execute your capability's test plan or guarantee that its tests will pass.

When an automated run cannot finish

  1. Open Virtualization, select Check prerequisites, and resolve any missing components.
  2. Select Refresh VM status. Start the VM if it is stopped and wait for the operation to finish. The first start can take longer while the base image downloads.
  3. Open Ansible diagnostics. Check connectivity, then run the validation playbook. Expand Last operation output to inspect a failed step.
  4. Return to Test Runs. Retry a queued run, or create a new run if the previous one has finished or failed.
  5. Open the run details and inspect each case's expected result, actual result, standard output, and standard error.

Only one infrastructure operation can run at a time. If CAPTEX reports that the VM is busy, wait for the current operation to finish before retrying.

A FAIL result means a test's expectation was not met; inspect the capability and test case. An ERROR result can indicate a timeout or execution problem. The deliberately broken Text Summary example is expected to fail its word-count check.

CAPTEX stops a VM it started for an automated run. A VM you started manually remains running afterward; use Stop VM when you have finished with it.
